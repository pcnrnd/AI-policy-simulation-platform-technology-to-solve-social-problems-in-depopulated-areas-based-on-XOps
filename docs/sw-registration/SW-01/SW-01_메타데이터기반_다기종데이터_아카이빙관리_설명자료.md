## 1. 목적

다기종(관계형·문서형·공간·시계열) 데이터를 저장소별로 각각 연동하지 않고, **메타데이터 카탈로그 하나로 검색·CRUD 대상을 결정**하는 아카이빙·통합처리 프로그램이다. 사용 화면·연동 시스템은 데이터가 어느 DB에 있는지 몰라도 카탈로그의 소스 id만으로 조회·등록·수정·삭제를 수행한다.

## 2. 주요기능

| 기능 | 설명 | 근거 |
|---|---|---|
| 메타데이터 카탈로그 검색·조회 | 소스 id·태그·설명·객체명 부분 일치 검색, 기본 목록은 실데이터+사용자 등록 소스이며 `include_seed=true`일 때 데모 시드(`is_seed`)까지 노출 | `src/dataops/catalog.py` |
| 실적재 행수 확인 | `live=true`이면 카탈로그 소스의 `object`를 해당 저장소에서 세어 "등록됨"과 "적재됨"을 구분. 확인 불가(DSN·드라이버 부재)는 0과 구분해 `None` | `src/dataops/liveness.py` |
| 신규 아카이브 등록 | Tier(Hot/Warm/Cold)·보존기간·컬럼 정의를 받아 즉시 CRUD 대상으로 편입 | `src/schemas/dataops.py`(`ArchiveRegisterRequest`), `POST /dataops/catalog` |
| 다기종 저장소 자동 라우팅 | 스키마의 저장소 유형 문자열로 PostgreSQL/PostGIS/TimescaleDB/MongoDB 어댑터를 자동 선택 | `src/dataops/adapters.py` |
| Data API Builder (표준 REST CRUD) | GET/POST/PUT/PATCH/DELETE를 필터(AND 결합 최대 5개)·정렬·페이징과 함께 표준 SQL/MQL로 생성·실행 | `src/dataops/query_builder.py`, `src/dataops/service.py` |
| 발급 API 구성 목록 | 발급한 API 구성의 서버 저장·조회·삭제(조회 `data:read`, 등록·삭제 `data:write`) | `GET/POST /dataops/apis`, `DELETE /dataops/apis/{api_id}` |
| 3중 SQL 인젝션 방어 | 등록(422)·실행(400)·생성 SQL 최종 검사 3단계로 카탈로그 자체를 신뢰하지 않고 검증 | `src/dataops/safety.py` |
| 실 저장소 미연결 시 결정적 대체 응답 | DSN·드라이버 부재 시 In-Memory 어댑터로 낮춰 API 계약을 유지 | `src/dataops/adapters.py`(`InMemoryAdapter`) |
| JWT/OAuth2 인증 발급 | 소스별 접근 토큰 발급(HS256, scope `data:read`/`data:write`). 미존재 소스에는 발급하지 않음. prod는 설정된 클라이언트 자격증명 검사 | `src/api/v3/dataops.py`, `src/auth/jwt.py` |
| 실 공공데이터 아카이빙 적재 | 통계청 행정구역경계·복지시설·BC카드/KT/GWTO 테이블 적재 스크립트 | `platform/scripts/load_real_data.py`, `load_external_data.py` |

## 3. 특징

- **저장소 비의존 API 계약** — 응답 스키마(`db_adapter`·`generated_query`·`source_kind` 등)가 저장소 종류·연결 여부와 무관하게 동일하다. 실 DB가 없어도 계약을 검증할 수 있다(In-Memory degrade). 실제 저장소 조회 여부는 응답의 `source_kind`로 구분한다.
- **카탈로그 등록이 곧 API 확장** — 새 데이터셋은 엔드포인트 추가 없이 카탈로그 등록만으로 CRUD 대상이 된다.
- **카탈로그를 신뢰하지 않는 방어 설계** — 사용자가 등록한 object·컬럼명·range 값이 생성 SQL에 조립되는 경로 자체를 3중으로 검증한다(등록 시점 pydantic 패턴 + 실행 직전 재검증 + 생성 SQL 최종 검사).
- **표시용·실행용 쿼리의 같은 입력 생성** — 표시 문자열(`generated_query`)과 실행 문자열을 같은 입력에서 각각 만들어, 화면에 보이는 쿼리와 실제 실행 쿼리의 불일치를 구조적으로 막는다.

## 4. 사용방법

단독 실행은 [README.md](README.md)를 따른다. 요약:

```powershell
Set-Location platform/backend/xops-service
python -m pip install -r requirements.txt
python -m uvicorn sw_main:create_sw01_app --factory --port 8001
```

카탈로그 조회 → 토큰 발급 → CRUD 순서로 사용한다.

```powershell
curl "http://localhost:8001/api/v3/dataops/catalog"
curl -X POST "http://localhost:8001/api/v3/dataops/token/ds_10_bccard_dong_industry_sales"
curl -H "Authorization: Bearer <TOKEN>" "http://localhost:8001/api/v3/dataops/ds_10_bccard_dong_industry_sales?page=1&page_size=20"
```

실 저장소 연결이 필요하면 `pip install -r requirements-db.txt` 후 `XOPS_PG_DSN`/`XOPS_MONGO_URI`/`XOPS_TIMESCALE_DSN`으로 DSN을 지정한다(미지정 시 In-Memory 응답).

## 7. 2025년 등록 「데이터 워크플로우 관리 프로그램」과의 차별점

2025-11-07 창작완료·공표된 기존 등록 SW(등록 명세서상 프로그램명 「데이터 통합 및 버전 관리 워크플로우 시스템」)는 **Airflow 기반 DAG 오케스트레이션 + DVC/Git 데이터 버전관리 + 컨테이너 태스크 격리**가 핵심 구성기술이다(위키 `population-decline-history.md` §7). 즉 등록된 것은 "파이프라인 실행·재현성 관리 엔진"이다.

| 구분 | 2025 등록 SW | SW-01(본 신규) |
|---|---|---|
| 핵심 자산 | Airflow DAG·스케줄러·트리거, DVC 해시 기반 버전관리·재현성 | 메타데이터 카탈로그 + Data API Builder(저장소 추상화 CRUD) |
| 실행 단위 | Docker Compose로 격리된 태스크(Airflow Task) | FastAPI 엔드포인트(요청 단위 처리, 워크플로 스케줄링 없음) |
| 의존 스택 | Apache Airflow, PostgreSQL, Redis, MinIO, Git, DVC | fastapi/uvicorn/pydantic (필수), psycopg/pymongo(선택) |
| 문제의식 | "파이프라인 실행을 어떻게 스케줄링·재현하는가" | "다기종 저장소를 API 사용자에게 어떻게 하나의 계약으로 감추는가" |
| 코드 위치 | (2025) Airflow DAG·오퍼레이터 정의(본 저장소 범위 밖 — 위키 참조) | `src/dataops/*`(본 저장소, 2026-06 이후 커밋) |

두 프로그램은 겹치는 코드가 없고(Airflow DAG 대 FastAPI 라우터·어댑터), 다루는 문제도 다르다. [확인 필요] 2025 등록 명세서 원문을 직접 열람하지 않았으며, 위 비교는 `population-decline-history.md` §7 요약 인용에 근거한다.

## 8. 독립 실행 가능성

- `sw_main:create_sw01_app`은 `/api/v3/dataops`만 등록한 FastAPI 앱을 띄운다. 이 진입점은 `src.mlops`·`src.realdata`·모니터링 라우터를 import하지 않으며, 새 인터프리터에서 `sys.modules`로 이를 검사하는 테스트가 있다(`tests/integration/test_sw_entrypoints.py`).
- 공유 기반(`src/core`, `src/auth`)은 SW-02와 같은 코드를 쓴다. 같은 `XOPS_DB_PATH`를 가리키면 SQLite 파일도 공유한다.
- 통합 플랫폼 실행(`main:app`, Compose)은 그대로 전체 라우터를 한 프로세스로 띄운다.
- **[확인 필요]** SW 등록 신청서의 "독립적으로 실행 가능한 프로그램" 기준 충족 여부는 신청서 서식과 담당자 확인이 필요하다.
