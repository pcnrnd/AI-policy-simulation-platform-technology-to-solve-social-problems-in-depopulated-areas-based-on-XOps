# 사회문제 해결지원 시뮬레이션 공간정보 표현 프로그램

DB 시설 유형을 그룹으로 나눠 지도에 표시하고, 읍면동별 접근 거리로 부족 지역을 찾아, 시설을 추가했을 때의 변화를 그래프로 보여 주는 프로그램이다. 화면(Vite·React)과 읽기 전용 로컬 API(`api.js`) 두 부분으로 동작한다. 지역은 왼쪽 요약 상자 맨 위에서 시군구를 여러 개(최대 5곳) 골라 한 지도에서 함께 계산하며, 처음은 `REGION_CODE`(기본 지역) 하나다. 코드에 특정 지역 값을 두지 않는다.

> **자료**
> - 인구(읽기만, 저장소에 올리지 않음): 행정안전부 「지역별(행정동) 성별 연령별 주민등록 인구수」(공공데이터포털 15097972 https://www.data.go.kr/data/15097972/fileData.do , CSV, 매월 갱신, 지금 파일 2026-10-31 기준, 이용허락범위 제한 없음, 키·로그인 없이 내려받음). 행정동(행정기관코드 10자리)마다 계·남녀 1세 단위(0~109세, 110세 이상) 인구다. `data/pop/`에 두면 API가 시작할 때 한 번 읽어 9구간(0~9·10~19·20~29·30~39·40~49·50~64·65~74·75~84·85세 이상, 합 = 계)과 여성 20~29·30~39·40~49세로 모은다. 남원시 합계 73,294명은 이전에 쓰던 DB 인구 표(2026-10)와 같다.
> - DB(flows MariaDB, 읽기만): 고른 시군구의 노인 돌봄 시설(`ingu_fclty_oldman`)만 읽는다. 시설 이름은 유형+번호로 표시하고 기관명·주소·전화 열은 읽지 않는다. 좌표는 웹 메르카토르(EPSG:3857)를 위경도로 바꾼다. 인구 표(`ingu_cnt_gender`)·주소 코드표는 더 쓰지 않는다.
> - 의료·보건 시설(읽기만, 저장소에 올리지 않음): 건강보험심사평가원 「전국 병의원 및 약국 현황」(공공데이터포털 https://www.data.go.kr/data/15051059/fileData.do , 2026-09-30 기준, 키·로그인 없이 내려받음). 이용 조건은 공공누리 제1유형(출처표시)이며, 이용·재배포할 때 "출처: 건강보험심사평가원, 전국 병의원 및 약국 현황(공공데이터포털)"을 표시한다. 내려받은 zip에서 `1.병원정보서비스`·`2.약국정보서비스`·`5.의료기관별상세정보서비스_03_진료과목정보` CSV 세 개를 `data/hira/`에 둔다(cp949 그대로). API가 첫 요청 때 한 번 읽고, 시군구마다 그 지역 행만 골라 둔다. HIRA 시군구 코드는 행정 코드가 아니라서 인구 파일의 시도·시군구 이름으로 거른다(시도는 `전북`↔`전북특별자치도`, `광주`↔`전남광주통합특별시`처럼 줄임 이름을 맞추고, 구는 HIRA가 시·광역시 이름을 붙여 쓰므로 `수원시 장안구`→`수원장안구`, 부산 `서구`→`부산서구`, `세종특별자치시`→`세종시`로 맞춤 — 256개 시군구 모두 1곳 이상 맞음). 기관명·주소·전화는 화면에 쓰지 않는다. 파일이 없으면 의료·보건 그룹 없이 동작한다.
> - 청년 지원 시설 그룹(청년 주택·일자리 거점·교육·연수 시설·창업 공간·문화·체육 시설)은 실제 기관·장소 자료가 아니다. 위치는 화면이 지역 코드로 만든 예시 시설(아래 "예시 자료")이고, 1곳당 정주·생활인구는 아래 "가정"의 고정 가정값을 쓴다(화면에서 바꾸지 않음).
> - 시군구 코드: 인구 파일·경계는 새 코드, DB 시설 표는 옛 코드가 남아 있다. 옛 코드 = 새 코드의 앞 2자리를 52→45, 51→42로 바꾼 값(나머지 지역은 같음). 시설은 두 코드 모두로 찾는다.
> - 행정동 경계(읽기만, 저장소에 올리지 않음): [vuski/admdongkor](https://github.com/vuski/admdongkor)의 `HangJeongDong_ver*.geojson`(전국 3,559곳). API가 시작할 때 전국을 읽어 시군구별로 나눠 두고, 고른 시군구 경계만 화면에 준다. 이용 조건은 데이터 CC BY 4.0(원자료 통계청 SGIS 공공누리 제1유형, 출처표시 의무 승계)이며, 이용·재배포할 때 저장소 `LICENSE-DATA` §3의 출처 표기를 보존한다:
>   "본 데이터는 통계청 통계지리정보서비스(SGIS, https://sgis.kostat.go.kr)에서 공공누리 제1유형으로 개방한 행정동 경계를 가공한 것이며(가공: vuski/admdongkor, https://github.com/vuski/admdongkor), CC BY 4.0으로 배포됩니다."
> - 읍면동 단위는 행정동이다. 인구 행정기관코드와 경계 `adm_cd2`(10자리)를 맞추고, 대표 지점은 모두 그 행정동 경계 안 중심점이다. 인구 파일 3,620행 가운데 경계가 없는 62행은 57행이 출장소라 같은 시군구에서 이름이 앞부분인 행정동(부모 읍면동, 예: 돌산읍우두출장소 → 돌산읍)에 합치고, 나머지 5행(평택시 고덕1동·고덕2동 — 경계 파일은 예전 고덕동 하나, 보령시 원산출장소·사천시 신수출장소·밀양시 삼랑진임천출장소)은 위치가 없어 지도·계산에서 빠진다. 경계에만 있는 곳은 평택시 고덕동 1곳(인구 없음)이다.
> - 시설(DB 노인 돌봄·HIRA·청년 지원 시설 예시)은 좌표로 고른 시군구의 행정동 경계 안에 넣어 그 행정동에 배정한다. 경계 밖 좌표 시설과 추가 시설은 가장 가까운 대표 지점의 행정동이다.
> - 그룹은 DB 시설 유형 이름을 아래 "시설 그룹 묶음" 규칙으로 묶어 만든다. 지역이 바뀌어도 같은 규칙을 쓰고, 시설이 없는 그룹은 나오지 않는다.
> - 인구 파일의 256개 시군구 모두 고를 수 있다. DB 노인 돌봄 시설이 없는 시군구는 노인 돌봄 그룹이 나오지 않는다.
> - 인구감소지역(2026-10-07 재지정 92곳) 표시는 넣지 않았다. 키·로그인 없이 받을 공식 명단 파일을 확인하지 못했다.
> - 배경지도(OpenStreetMap 타일)는 항상 켜져 있다. 화면 데이터가 모두 실제 값이라 켜기·끄기 버튼을 두지 않는다.
>
> 화면에는 자료 안내·계산 기준·한계 문구를 두지 않는다. 그런 설명은 이 README에만 둔다.

## 실행

PowerShell 7에서 한 번에(비밀번호는 입력할 때 가려지고 기록에 남지 않는다):

```powershell
cd project/simulation_spatial
npm install
# 행정동 경계(처음 한 번, 약 35MB, data/는 저장소에 올리지 않음). 새 판이 나오면 ver 날짜만 바꿔 받는다.
New-Item -ItemType Directory -Force data | Out-Null
Invoke-WebRequest https://raw.githubusercontent.com/vuski/admdongkor/master/ver20261001/HangJeongDong_ver20261001.geojson -OutFile data/HangJeongDong_ver20261001.geojson
# 행정동 인구(처음 한 번·매월 새 판, 약 2.5MB, cp949). 공공데이터포털 15097972 화면의 내려받기와 같은 파일이다.
New-Item -ItemType Directory -Force data/pop | Out-Null
Invoke-WebRequest "https://www.data.go.kr/cmm/cmm/fileDownload.do?atchFileId=FILE_000000007754360&fileDetailSn=1&insertDataPrcus=N" -OutFile "data/pop/지역별(행정동) 성별 연령별 주민등록 인구수_20261031.csv"
$env:DB_USER = "<DB 계정>"
$env:DB_PASSWORD = Read-Host -MaskInput "DB 비밀번호"
$env:REGION_CODE = "52190"                             # 기본 시군구 코드 5자리(새 코드)
Start-Process node -ArgumentList api.js -NoNewWindow   # API http://127.0.0.1:5182/api/data?regions=52190,52130
npm run dev                                            # 화면 http://localhost:5180
```

- `.env`로 실행할 때는 `.env`에 `REGION_CODE=52190` 한 줄을 넣고 `node --env-file=.env api.js`로 띄운다(`.env`는 저장소에 올리지 않는다).
- API 환경변수: `DB_USER`·`DB_PASSWORD`·`REGION_CODE`(필수), `DB_HOST`(기본 127.0.0.1), `DB_PORT`(기본 3310), `DB_NAME`(기본 flows), `API_PORT`(기본 5182), `BOUNDARY_FILE`(기본 `data/`의 가장 최신 `HangJeongDong_ver*.geojson`, 없으면 경계 없이 동작), `HIRA_DIR`(기본 `data/hira/`, 병의원·약국·진료과목 CSV 폴더, 없으면 의료·보건 시설 없이 동작), `POP_FILE`(기본 `data/pop/`의 가장 최신 `…주민등록 인구수_*.csv`, 없으면 안내 한 줄을 내고 종료). 경계·인구는 시작할 때, 병의원·약국은 첫 요청 때 한 번 읽으므로 파일을 바꾸면 API를 다시 띄운다(시작 약 0.7초, 첫 요청 HIRA 읽기 약 4초). 접속 정보는 환경변수로만 받고 파일·로그에 쓰지 않는다. 필수 값이 없으면 안내 한 줄을 내고 종료한다.
- 지역은 화면 왼쪽 요약 상자 맨 위에서 고른다(아래 "화면 구성"). API는 `/api/data?regions=코드,코드`(5자리 시군구 코드, 인구 파일에 있는 것만, 최대 8곳)를 받고, 값이 없으면 `REGION_CODE` 하나다. 맞는 코드가 없으면 400. 지도 중심·확대는 고른 지역 경계 범위에 맞춰진다.
- API는 `SELECT`·`SHOW`만 쓰고 세션을 읽기 전용으로 연다. 화면은 `/api` 요청을 Vite 프록시로 API에 넘긴다.
- API 없이 화면만 띄우면 시설이 비고 왼쪽에 "자료를 불러오지 못했습니다. 새로 고침해 주세요."가 나온다.
- `make run-simulation-spatial` (`project/` 에서) — 설치 후 화면 개발 서버 실행(API는 위처럼 따로 실행)
- `npm run build` → `dist/`, `npm run preview` → http://localhost:5181
- `npm test` — 계산 규칙 시험(Node 18 이상 내장 `node:test`)
- 배경지도는 인터넷 연결이 있으면 늘 보이고, OpenStreetMap 이용 조건에 따라 지도 오른쪽 아래에 출처가 나온다. 연결이 없으면 배경 타일만 빈 칸이 되고 오류 문구는 나오지 않는다.
- 빌드 결과(`dist/`)를 정적 배포할 때는 `/api`를 API로 넘기는 프록시를 함께 둔다.

## 기능

1. **공간정보 화면표시**: DB 시설 유형을 이름 키워드로 묶은 그룹(아래 표)과 유형 분류, 그룹 상세 목록에서 시설을 골라 지도에 표시, 좌(선택)·우(상세) 화면 구성.
2. **요인별 변화 시뮬레이션**
   - 지역 선택: 시군구를 여러 개(최대 5곳) 골라 한 지도에서 함께 계산.
   - 시뮬레이션 환경변수 입력: 유형별 기준 거리(0.3~5km), 부족 판정 최소 대상 인구(범위는 아래 "지도 표시 기준"처럼 데이터에 맞춤), 인구 증감 9구간 증감률(−50~+50%, 모든 시설 공통).
   - 시설 추가·전환: 읍면동(대표 지점)이나 격자를 골라 어느 유형이든(청년 지원 시설 유형 포함) "추가", 기존 시설을 다른 유형으로 "전환". 추가 삭제·전환 되돌리기.
   - 추가·전환 효과: 기준 거리 밖 대상 인구·부족 읍면동·평균 거리, 시설 사용률, 정주인구·생활인구 유입을 전·후 숫자와 그래프로 비교하고, 지도에 유입 읍면동·사용률·배정 연결로 보인다.
   - 부족 지역 표시: 한 화면에서 읍면동 원을 판정 3가지(부족 빨강 · `{r}km 이내` 초록 · `{r}km 밖·{n}명 미만` 회색)로 칠하고, 격자는 최근접 시설까지 거리 4구간으로 칠한다. 세 조건이 모두 이 화면에 나타난다: 기준 거리 → 격자 구간·판정, 증감률 → 원 크기·판정, 최소 대상 인구 → 판정.

## 조건의 뜻

화면에는 설명 문장을 두지 않으므로 조건 값이 무엇을 재는지는 여기에 적는다. 조절하는 동안 지도에 그 뜻이 그려진다(아래 "지도 표시 기준").

- **대상 인구**: 고른 시설 유형의 대상 연령층에 사는 인구, 행정동마다. 노인 돌봄 시설은 모두 65세 이상(65~74·75~84·85세 이상)이다. 의료·보건 시설 가운데 보건기관·의원·약국은 전체 인구, 산부인과는 20~49세 여성, 청년 지원 시설은 20~49세다. 이용자·수급자 수가 아니다. 화면에서 이 값은 어디서나 "대상 인구"로 부르고, 왼쪽 위 머리줄에 대상 연령층(`65세 이상`, `전체 인구`, `20~49세`, `20~49세 여성`, 아동 대상이면 `0~9세`)을 적는다. 인구 증감과 유입 시설의 정주인구가 이 값을 바꾼다(아래).
- **인구 증감(9구간 가정)**: 시설이 아니라 지역 인구에 대한 가정이라 ◉ 시설과 관계없이 늘 9구간(0~9·10~19·20~29·30~39·40~49·50~64·65~74·75~84·85세 이상, 합 = 전체 인구)을 보인다. 값은 구간마다 하나이고 모든 시설이 같이 쓴다(전체 인구의 20~29세와 산부인과·청년 지원 시설의 20~29세는 같은 값). 각 시설의 대상 인구는 그 대상 구간만 곱한다. 그래서 대상 밖 줄을 바꿔도 그 시설 결과는 그대로이고(조건 카드에서 흐린 줄), 9줄에 같은 비율을 주면 어느 대상이든 대상 인구 × (1 + 비율)과 같다(시험). 구간마다 다르게 주면 연령 구성이 다른 행정동끼리 다르게 바뀐다. 거리는 바뀌지 않는다.
- **노인 65세 기준**: 1세 단위 인구라 법정 노인 기준 65세에서 끊는다(이전 DB 인구 표는 10세 구간이라 70세였다). 65~74·75~84·85세 이상으로 나눈다.
- **여성 대상(산부인과)**: 20~29·30~39·40~49세 여성 인구. 증감률은 같은 구간의 여성 인구에 곱한다.
- **여러 지역**: 고른 시군구들을 한 지도·한 계산으로 합친다. 행정동·시설·격자는 고른 시군구 것만 쓰고, 가장 가까운 시설은 고른 시군구 안의 모든 시설에서 찾는다(고른 시군구 밖 시설은 쓰지 않아, 시군구 경계 가까운 행정동은 실제보다 멀게 나올 수 있다). 사용률 수용은 고른 시군구 전체로 다시 잡는다(처음 평균 100%). 추가·전환 동작은 지역을 바꿔도 남기되, 고른 시군구 밖 동작(추가 자리가 경계 밖이거나 전환한 원래 시설이 없음)은 계산과 `추가 시설` 목록에서 빠지고, 그 시군구를 다시 고르면 돌아온다. 유형·시설 id는 유형 이름·좌표로 정해 지역을 바꿔도 같다(기준 거리·◉·동작이 이어짐).
- **청년 지원 시설과 정주인구·생활인구**: 청년 지원 시설 그룹의 유형(청년 주택·일자리 거점·교육·연수 시설·창업 공간·문화·체육 시설)은 청년이 들어오게 하는 시설을 일반 이름으로 둔 것이다. 지금 있는(예시) 시설은 이미 반영된 것으로 보아 유입을 더하지 않고, 새로 추가하거나 다른 시설을 이 유형으로 전환했을 때만 유입이 생긴다. 이 유형을 ◉로 고르면 대상 인구는 20~49세다. 1곳당 정주인구는 그 시설 1곳이 새로 생기면 그 읍면동에 새로 사는 청년 수이고, 청년 구간 비중대로 20~29·30~39·40~49세에 나눠 그 읍면동 대상 인구에 더한다(증감률은 곱하지 않음, 노인 대상에는 더하지 않음, 산부인과 대상은 그 구간 지금 여성 비율만큼). 그래서 의료·보건 유형의 부족 판정·사용률이 따라 바뀐다. 1곳당 생활인구는 살지는 않고 일·교육·여가로 그 읍면동에 머무는 사람 수로, 대상 인구에는 더하지 않고 읍면동별 `생활인구 유입`으로 따로 보인다.
- **결과 지표(`변화` 띠)**: 시뮬레이션 결과는 세 가지이고, 입력은 인구 증감과 시설 추가·전환뿐이다(정주·생활은 입력이 아니라 결과). ① 평균 사용률 = 분석 기준 시설 사용률의 평균(`meanRate`, 처음 100%). 분석 기준 대상 구간의 인구 증감과 시설 추가·전환이 바꾼다(대상 밖 구간 증감은 바꾸지 않음). ② 정주인구 변화 = 인구 증감으로 늘거나 준 주민 수(모든 읍면동·9구간 Σ 구간 인구 × 증감률, `growthByDong`) + 청년 지원 시설 정주 유입(1곳당 고정 가정값)이고, 분석 기준과 관계없다(`settledChange`). 읍면동 상세 `정주인구 변화`도 그 읍면동의 같은 합이다. ③ 생활인구 변화 = 청년 지원 시설 생활 유입(1곳당 고정 가정값). 띠는 처음 상태(추가·전환 0, 증감 0)와 다를 때만 보인다(`changeVisible`). 남원 방문요양서비스: 20~29세 +10% → 사용률 100% 그대로·정주인구 +518명, 65~74세 +10% → 사용률 105%(+5%p)·정주인구 +1,332명, 청년 주택 1곳 추가 → 정주 +100명·생활 +20명.
- **추가와 전환**: 추가는 고른 자리(읍면동 대표 지점 또는 격자 중심)에 시설 1곳을 새로 두는 것, 전환은 기존 시설 1곳을 같은 자리·같은 소재 읍면동에서 다른 유형으로 바꾸는 것이다. 전환하면 원래 유형에서는 그 시설이 빠져 원래 유형의 접근·사용률도 바뀐다.
- **시설 사용률**: 시설마다 맡는 수요가 1곳당 수용 능력의 몇 배인지. 읍면동마다 가장 가까운 같은 유형 시설에 그 읍면동 대상 인구를 배정해 시설별로 더한 값(배정 수요)을 1곳당 수용으로 나눈다. 가장 가까운 시설이 같은 좌표에 여럿이면(같은 건물) 똑같이 나눈다. 1곳당 수용은 처음 상태(추가·전환·증감·유입 0)의 그 유형 대상 인구 합 ÷ 처음 시설 수라서, 처음에는 시설 평균 사용률이 100%다(상대 비교). 실제 이용자 수·정원이 아니다. 시내에 몰린 시설은 낮고, 넓은 면 지역을 혼자 맡는 시설은 수백 %로 높게 나온다.
- **최근접 시설까지 거리**: 행정동 대표 지점(경계 안 중심점)에서 고른 유형의 가장 가까운 시설까지의 직선거리. 도로 거리나 이동 시간이 아니다. 방문형 서비스(방문요양 등)에서는 제공자가 이용자 집까지 가는 거리로 읽는다.
- **부족 판정**: 조건 카드 한 묶음의 두 기준. 최근접 시설까지 거리가 `거리` 값보다 멀고, 대상 인구가 `대상 인구` 값 이상인 읍면동이 부족 지역이다. 요약 `{r}km 밖 대상 인구`·`부족 읍면동`, 범례 `부족 지역 · {r}km 밖·{n}명 이상`이 같은 기준을 쓴다.
- **조건은 잣대·가정이다.** 기준 거리와 최소 대상 인구는 부족을 가르는 잣대이고, 증감은 인구 변화 가정이다. 값 자체의 좋고 나쁨이 아니라, 같은 조건에서 시설을 추가하기 전·후 결과로 비교한다.
- **기준 거리 시작값(시·구 3km, 군 5km)**: 국토연구원 「국토이슈리포트」 제2호 『기초생활SOC 10분 내에 이용 가능한가? – 살기 좋은 삶터의 조건』(2018.10.12)이 기초생활SOC 접근성을 분석할 때 쓴 도로이동거리 기준 "시급도시는 3km, 군지역 5km"(차량 이동 10분 거리로 설정)를 따른다(원문: https://www.krihs.re.kr/galleryDownload.es?bid=0024&list_no=27785&seq=1 , 1·4쪽). 그 보고서는 도로이동거리이고 이 프로그램은 직선거리라 같은 값이라도 이 프로그램 쪽이 더 넓게 잡힌다. 지역 유형은 시군구 이름 끝 글자로 정한다(`regionStartKm`): `시`·`구`(광역시 자치구, `전주시 완산구` 같은 일반구, `세종특별자치시` 포함) → 3km, `군`(`기장군` 같은 광역시 군 포함) → 5km, 그 밖 → 3km(시험). 지역 하나를 고르면 그 값이 시작값이다(남원시 3km). 시와 군을 함께 고르면 거리 슬라이더를 움직이기 전까지 읍면동마다 자기 시군구 시작값으로 판정하고(행정동 코드 앞 5자리 = 시군구), 값 표시는 `3·5km`(조건 카드 `3·5km 초과`, 요약 `3·5km 밖 대상 인구`, 범례 `3·5km 이내`·`3·5~6·10km`…)로 둘 다 보인다. 슬라이더를 움직이면 모든 지역이 그 값 하나를 쓴다. 섞인 동안 격자 칸은 가장 가까운 읍면동 대표 지점의 시군구 값으로 칠하고, 시설 반경 원·`{r}km 이내 대상 인구`는 시설 소재 읍면동의 시군구 값, 읍면동 상세 `상태`는 그 읍면동 값을 쓴다. 유형별 거리 기억은 그대로라 슬라이더를 움직인 유형은 그 값을, 아닌 유형은 시작값을 쓴다.
- **최소 대상 인구(기본 20명)와 증감(기본 0%)**: 공식 기준을 찾지 못한 정책 가정값이다.

## 가정

실제 자료가 아닌 값이다. 화면에는 이름과 값만 두고 근거는 여기에만 적는다. 모두 화면에서 바꾸지 않는 고정 가정값이며, 실제 시설·지역의 사실이 아니다.

- **청년 지원 시설 유형별 기본값**(`src/lib/scenario.js` `INFLOW_KINDS`, 1곳당 정주인구·생활인구, 20~29·30~39·40~49세 비중): 둥근 가정값이다. 종류의 성격만 반영해 크기 순서를 정했고 통계에서 가져오지 않았다.

  | 종류 | 1곳당 정주인구 | 1곳당 생활인구 | 비중 20~29·30~39·40~49 | 근거(가정) |
  |---|---|---|---|---|
  | 청년 주택 | 100명 | 20명 | 50·40·10 | 사는 시설이라 정주가 가장 크고 방문은 적음, 입주는 20~30대 중심 |
  | 일자리 거점 | 30명 | 300명 | 30·40·30 | 통근 인원이 많고 일부만 옮겨 와 삶, 연령이 고르게 퍼짐 |
  | 교육·연수 시설 | 20명 | 200명 | 70·20·10 | 수강·연수로 머무는 사람이 많고 기숙 일부, 20대 중심 |
  | 창업 공간 | 10명 | 100명 | 40·40·20 | 입주 팀 단위라 규모가 작음 |
  | 문화·체육 시설 | 0명 | 500명 | 40·30·30 | 이용만 하고 살지 않음, 방문이 가장 많음 |
- **비중**: 세 값의 합으로 나눠 쓴다(합이 100이 아니어도 됨, 모두 0이면 똑같이 나눔).
- **사용률 3단계**(`USAGE_LEVELS`): 70% 미만 / 70~130% / 130% 초과. 처음 평균이 100%가 되게 수용을 잡았으므로, 평균에서 ±30% 안을 "보통"으로 본 가정이다. 지도 ◉ 유형 시설 점 테두리(옅은 회색 / 짙은 회색 / 검정 굵게)와 범례 한 줄이 이 기준을 쓴다.
- **이용 비율을 두지 않은 이유**: "배정 수요 = 대상 인구 × 이용 비율"로 두어도 1곳당 수용(= 처음 배정 수요 평균)에 같은 비율이 곱해져 사용률에서 지워진다. 그래서 값이 결과에 영향을 주지 않는 가정을 두지 않았다.

## 예시 자료

청년 지원 시설 그룹의 시설 위치는 실제 자료가 없어 화면이 만든다(`src/lib/scenario.js` `exampleInflowFacilities`). API·DB·data 폴더는 쓰지 않는다. 화면 이름은 유형+번호(`청년 주택 01`)이고 "예시" 표시는 화면에 두지 않는다.

- 수: 청년 주택 4, 일자리 거점 3, 교육·연수 시설 2, 창업 공간 3, 문화·체육 시설 4곳(`EXAMPLE_COUNTS`, 합 16).
- 자리: 대표 지점이 있고 20~49세 인구가 있는 읍면동을 20~49세 인구에 비례한 확률로 하나 뽑아, 그 대표 지점에서 0.3~0.8km 떨어진 임의 방향에 둔다(같은 읍면동에 여러 곳이 갈 수 있음). 소재 읍면동은 뽑은 읍면동이다.
- 시드: 난수는 문자열 `youth-{고른 시군구 코드를 쉼표로 이은 것}`(남원만이면 `youth-52190`)의 FNV-1a 해시를 시드로 한 mulberry32다. 같은 지역을 고르면 늘 같은 자리, 지역을 바꾸면 그 지역 행정동에 같은 규칙으로 다시 생긴다(시험, 수는 고른 지역 수와 관계없이 같음). 인구 자료가 없으면 만들지 않는다.
- 예시 시설은 지금 있는 시설로 보고 유입을 더하지 않는다. 그래서 처음 화면의 다른 유형 결과는 예시 시설이 없을 때와 같다. 사용률 수용은 예시 시설 수로 나눈다(처음 평균 100%).
- 남원(52190) 처음 화면에서 청년 지원 시설 유형을 ◉로 골랐을 때(3km·20명·0%, 행정동 단위): 청년 주택 6,162명·17곳·3.50km, 일자리 거점 11,555명·17곳·4.18km, 교육·연수 시설 12,194명·21곳·4.86km, 창업 공간 6,088명·16곳·3.60km, 문화·체육 시설 9,907명·16곳·3.38km(요약 숫자 3개). 행정동 단위로 바뀌며 뽑는 읍면동과 인구가 달라져 5-25 법정동 값과 다르다.

## 계산 규칙

예측·최적화 모델을 쓰지 않은 규칙 계산이며, 결과는 정책 효과 예측이 아니다. 식은 `src/lib/spatial.js`와 이 절에 같은 내용으로 있다. 계산 단위는 고른 시군구의 행정동이다.

- 거리: 두 지점 사이 직선거리(km, 등장방형 근사). 행정동 거리는 대표 지점에서 잰다.
- 대표 지점(`src/lib/boundary.js` `boundaryAnchors`·`interiorPoint`, API가 행정동 인구에 붙임, `spatial.js` `dongUnits`): 그 행정동 경계 안 중심점 = 가장 큰 조각의 무게중심, 무게중심이 경계 밖이면(오목한 모양) 같은 위도에서 경계 안을 지나는 가장 긴 구간의 가운데.
- 경계가 없는 행정동(전국 5곳, 위 "자료")은 위치가 없어 대상 인구 합계·거리 구간·부족 판정·평균 거리·사용률 배정·미리 보기에서 빠지고 지도 원도 없다(`accessSummary`·`usage`).
- `{r}km 밖 대상 인구`(요약 첫 숫자) = 대표 지점에서 최근접 같은 유형 시설까지 거리 > 기준 거리인 읍면동의 대상 인구 합 = 대표 지점이 있는 읍면동 대상 인구 − 기준 거리 안 대상 인구.
- 대상 인구(`targetPop`) = Σ 대상 연령 구간 인구 × (1 + 그 구간 증감률/100) + 그 읍면동 정주인구 유입 가운데 대상 구간 인원. 구간은 인구 증감 9구간(`src/lib/ingu.js` `ALL_BANDS`, API `src/lib/population.js` `POP_BANDS`와 같은 id) 가운데 대상의 것: 노인 돌봄 65~74·75~84·85세 이상(합 = 65세 이상 인구), 전체 인구 9구간(합 = 총인구), 20~49세·20~49세 여성 20~29·30~39·40~49세(여성은 여성 인구), 아동 0~9세(`AGE_BANDS`). 증감률은 구간마다 하나이고 모든 유형이 같이 쓰며, 기본값은 모두 0이다. 요약·판정·추가·전환 미리 보기·시설 상세·조절 중 숫자가 모두 이 함수를 쓴다(정주인구 유입은 `src/lib/scenario.js` `withInflow`가 계산 단위에 붙인 값을 이 함수가 더함). 시험: 9구간에 같은 값을 주면 어느 대상이든 대상 인구 × (1 + 값)과 같다, 대상 밖 구간을 바꿔도 그 대상 결과는 그대로다, 유입 0이면 유입 전과 같다, 노인 대상 결과는 청년 지원 시설 유입과 무관하다.
- 시나리오(`scenario.js` `scenarioState`): 동작 목록(추가 `{ kind: "add", to, lat, lng }`, 전환 `{ kind: "convert", from, to }`)을 기존 시설(예시 청년 지원 시설 포함)에 적용한다. 시설 = 기존 − 전환된 시설 + 추가·전환된 시설(전환은 원래 시설의 자리·소재 읍면동 그대로), 유입 배치 = 그 가운데 청년 지원 시설 유형인 것. 기존 청년 지원 시설은 유입 배치가 아니다. 동작이 없으면 기존 시설·계산 단위가 그대로다(시험).
- 정주인구 유입(`settledByDong`) = 읍면동마다 Σ 그 읍면동 유입 배치 × 1곳당 정주인구(고정 가정값 `INFLOW_SETTINGS`) × 구간 비중(비중 합으로 나눔). 대상 인구에는 대상 구간 인원만 더하고, 20~49세 여성 대상은 유입 인원 × 그 읍면동 같은 구간 지금 여성 인구 ÷ 그 구간 인구를 더한다. 예: 의원(전체 인구)에서 기준 거리 밖 행정동에 청년 주택 1곳 → 그 행정동 대상 인구 +100명, 요약 첫 숫자 +100명.
- 생활인구 유입(`livingByDong`) = 읍면동마다 Σ 유입 배치 × 1곳당 생활인구(고정 가정값). 대상 인구·판정·사용률에 들어가지 않는다(시험).
- 정주인구 변화(`growthByDong` + `settledChange`, `변화` 띠·읍면동 상세) = 읍면동마다 Σ 9구간 인구 × 그 구간 증감률/100(분석 기준과 관계없이 모든 구간) + 정주인구 유입. 평균 사용률(`meanRate`) = 분석 기준 시설 사용률의 평균(사용률이 있는 시설), 처음 상태는 1곳당 수용을 그렇게 잡았으므로 100%다(시험).
- 시설 사용률(`usage`) = 그 시설에 배정된 읍면동 대상 인구 합 ÷ 1곳당 수용(`capacityOf` = 처음 상태 대상 인구 합 ÷ 처음 시설 수). 배정 = 대표 지점에서 가장 가까운 같은 유형 시설(거리 차 1mm 안으로 같은 좌표인 시설이 여럿이면 수요를 똑같이 나눔). 추가한 시설도 같은 수용을 쓴다. 영향 시설(`usageChanges`) = 동작 전후로 화면 사용률(% 정수)이 바뀐 시설과 새로 생기거나 빠진 시설(배정 읍면동만 바뀌고 사용률이 같으면 넣지 않음), `영향 시설 최고 사용률` = 그 시설들 가운데 가장 높은 사용률.
- 시설의 읍면동 = API가 좌표로 정한 행정동(`boundaryOfPoint`, 고른 시군구 경계 안). 경계 밖 좌표 시설과 추가 시설은 가장 가까운 대표 지점의 행정동, 전환 시설은 원래 시설의 행정동, 예시 청년 지원 시설은 뽑은 행정동.
- 부족 읍면동 = 대표 지점에서 최근접 같은 유형 시설까지 거리 > 기준 거리 이고 대상 인구 ≥ 최소 대상 인구(대표 지점이 있는 읍면동만).
- 그룹 분석(`scenario.js` `groupBasis`, `basisTypeIds`): 그룹 안 유형의 대상 인구가 모두 같으면 그 대상(노인 돌봄 그룹 65세 이상, 청년 지원 시설 20~49세), 섞여 있으면 전체 인구이고 대상이 다른 유형(의료·보건의 산부인과)은 그룹 공급에서 뺀다. 공급 = 그룹 공급 유형 시설 전부를 한 유형처럼 보고 위 규칙(최근접 거리·부족 판정·사용률)을 그대로 쓴다. 1곳당 수용 = 처음 상태 그룹 대상 인구 합 ÷ 처음 그룹 공급 시설 수(그룹 평균). 거리 기억은 그룹마다 따로이고 지역 유형별 시작값은 같게 쓴다. 요약은 `{그룹 이름} · {대상 연령층}`, 인구 증감 진한 줄은 그 대상 구간이다. 추가·전환 목록 기본값은 그룹 공급 유형 가운데 시설이 가장 많은 유형(`basisDefaultType`). 남원(3km·20명·0%): 방문 서비스 5,162명·6곳·2.01km(공급 111곳), 의료·보건 0명·0곳·1.28km(공급 136곳, 산부인과 6곳 뺌).
- 추가·전환 미리 보기 = 지금 동작 목록과 거기에 고른 동작 하나를 더한 목록으로 같은 계산을 두 번 한 값(기준 거리 밖 대상 인구, 부족 읍면동 수, 인구 가중 평균 거리, 영향 시설 최고 사용률·수, 정주·생활인구 유입 합, ◉ 유형 거리 구간별 인구). `추가 시설` 탭의 `처음과 지금`은 동작 0과 지금을 같은 식으로 비교한다.
- 거리 구간 = 기준 거리(r) 이내, r~2r, 2r~3r, 3r 초과. 화면 이름은 한 함수(`bandLabels`)가 지금 r 값으로 만들어 범례와 영향 그래프가 같이 쓴다(예: 2.9 → `2.9km 이내`/`2.9~5.8km`/`5.8~8.7km`/`8.7km 초과`, 소수 둘째 자리에서 반올림).
- 접근 거리 격자 = 고른 시군구 경계 범위에 깔고 칸 중심이 고른 시군구 경계 밖인 칸은 뺀다(경계가 없으면 데이터 범위(시설 좌표의 최소·최대)를 기준 거리만큼 넓힌 범위). 0.8km 칸(칸이 3,600개를 넘으면 칸을 키움)을 깔고, 칸 중심에서 최근접 같은 유형 시설까지 거리를 영향 그래프와 같은 4구간(`bandOf`: r 이내 / r~2r / 2r~3r / 3r 초과)으로 나눠 칠한다.
- 기준 거리 시작값(시·구 3km, 군 5km, 모든 유형 같음)은 화면에서 바꾸는 시작값이며 법정·행정 기준이 아니다.
- 기준 거리가 섞이면(위 "조건의 뜻") 거리 구간·상태 이름은 값들을 `·`로 잇는다(`bandLabels([3, 5])` → `3·5km 이내`/`3·5~6·10km`/`6·10~9·15km`/`9·15km 초과`).

### 지도 표시 기준

- 읍면동 상태(`dongStatus`, 지도 원 색과 선택 상세 "상태"가 같이 씀): 최근접 거리 ≤ 기준 거리 → `{r}km 이내`(초록), 아니고 대상 인구 ≥ 최소 대상 인구 → `부족 지역 · {r}km 밖·{n}명 이상`(빨강), 아니면 `{r}km 밖·{n}명 미만`(회색). 이름은 `dongStatusLabels`가 지금 조건 값으로 만든다. 부족 판정 규칙은 위와 같다. 최소 대상 인구를 올리면 먼 읍면동이 대상 인구 적은 순으로 빨강 → 회색이 된다.
- 기준 최댓값(`basePopMax`) = 증감률 0일 때 읍면동 대상 인구의 최댓값(대상 유형이 바뀌면 다시 계산). 원 반지름 = 7 + 13 × √(대상 인구 ÷ 기준 최댓값, 2까지) px. 그래서 증감률을 올리면 원이 커지고 내리면 작아진다.
- 최소 대상 인구 슬라이더(`minPopScale`): 눈금 단위 = 기준 최댓값 ÷ 100에 가장 가까운 1·2·5×10ⁿ(1 이상), 최댓값 = 기준 최댓값을 (눈금 단위 × 10) 단위로 올린 값, 간격 = 눈금 단위와 기본값 20명 가운데 작은 쪽(1·2·5·10·20, 모두 20을 나눠 기본값이 늘 눈금 위; 예: 839명 → 0~900, 10명 간격, 여러 지역 의원 25,000명 → 0~26,000, 20명 간격). 기본값 20명(`DEFAULT_MIN_POP`), 현재 값이 최댓값을 넘으면 최댓값으로 줄인다. 인구 자료가 없으면 0~200, 5명 간격.
- 여러 시군구를 고르면 행정동 경계선을 시군구마다 다른 색(8색 차례)으로 그려 시군구를 가른다. 범위 맞춤은 고른 시군구 경계 전체 범위다.
- 접근 거리 격자 색은 거리 4구간만 본다(파랑 한 계열, 가까울수록 연하게, 투명도 0.4 — 원의 판정 색과 겹치지 않게). 대상 인구·최소 대상 인구와는 무관하다. 대표 지점이 없는 읍면동은 지도에 원이 없다.
- 조절하는 동안의 그림(`MapControls.jsx` `useAdjust`, `MapView.jsx`): 슬라이더를 포인터로 잡고 있거나 키보드 포커스가 있을 때만 그리고, 포인터를 떼거나 포커스가 빠지면 지운다(터치는 뗀 뒤 0.8초 남김). 거리 → 고른 유형 시설마다(추가 시설 포함) 반경 r 원(시설 소재 시군구의 값)을 선택 시설 원과 같은 점선으로 옅게. 부족 판정 `대상 인구`·구간별 증감 슬라이더 어느 것이든 → 읍면동 원마다 대상 인구 숫자(증감·정주 유입 반영값)를 띄우고 최소 대상 인구 미만인 원을 흐리게.
- 시나리오(`MapView.jsx` `ScenarioLayer`, 늘 그림): 정주·생활인구 유입이 0보다 큰 읍면동 = 원 바깥 5px에 짙은 회색 점선 고리. 추가·전환한 시설을 고르면 그 시설에서 배정된 읍면동 대표 지점마다 점선(◉ 유형일 때), ◉가 아닌 청년 지원 시설이면 유입이 생긴 그 읍면동까지 점선. 청년 지원 시설은 다른 시설처럼 그룹 색 점이다. ◉ 유형 기존 시설 점의 테두리 = 사용률 3단계(아래 "가정"), 추가·전환 시설은 흰 바탕 굵은 유형색 테두리.
- `변화` 띠(`MapView.jsx` `ChangeStrip`): 지도 위 가운데 위쪽, 왼쪽은 확대 버튼 오른쪽(56px), 오른쪽은 겹침 묶음 폭(364px)을 비킨 칸 안 가운데 한 줄이다. 띠가 보이면 범위 맞춤 위쪽 여백을 띠 아래 끝까지로 잡고, 목록에서 고른 곳으로 옮길 때 띠도 범례처럼 원이 걸리면 안 되는 자리로 본다.
- 범례는 사용률·유입 줄을 늘 보인다. 첫 제목 `최근접 시설까지 거리`가 제목 줄이라 누르거나(키보드 Enter·Space) 접고 편다(처음은 펼침, 접으면 제목 한 줄과 `▾`). 범위 맞춤(범례 위쪽 끝까지 비킴)과 목록에서 고른 곳으로의 이동은 그때의 범례 높이(접혔으면 한 줄)를 쓰고, 펼칠 때 읍면동 원이 범례 밑에 들면 펼친 높이로 범위를 다시 맞춘다(1347×697에서 펼침·접힘 모두 범례 가림 0).
- 목록에서 시설을 고를 때의 이동(`src/lib/labels.js` `focusZoom`, `MapView.jsx` `MapSync`): 확대 단계를 12(지역 전체가 보이는 단계가 더 크면 그 단계)부터 0.5씩 지역 전체 단계까지 줄여 가며, 고른 시설을 겹침 묶음을 뺀 왼쪽 영역 가운데 → 범례 오른쪽 → 범례 위 → 범례 오른쪽 위 자리에 두어 보고, 어떤 읍면동 원도 범례에 걸리지 않는 첫 조합으로 옮긴다. 그런 조합이 없으면 처음 범위로 돌아간다. 1347×697에서 남원 방문요양서비스 33곳 중 20곳은 1.25~1.75단계 확대, 13곳은 처음 범위, 남원·군산·임실 94곳은 모두 1.5~3.5단계 확대, 범례 가림은 모두 0.
- 숫자 겹침 처리(`src/lib/labels.js` `placeLabels`): 대상 인구가 큰 원부터 숫자를 원 가운데 → 위 → 아래 → 오른쪽 → 왼쪽 자리에 놓아 보고, 이미 놓인 숫자나 범례·조건 카드와 겹치지 않는 첫 자리를 쓴다. 다섯 자리가 모두 겹치면 그 숫자는 띄우지 않는다(원이 몰린 시내에서 작은 값 몇 개가 빠짐, 확대하면 다시 자리를 잡는다).

## 시설 그룹 묶음

유형 이름에서 공백·가운뎃점을 뺀 뒤 위에서부터 처음 맞는 키워드의 그룹으로 보낸다(`src/lib/ingu.js` `GROUP_RULES`). 유형 예 가운데 단기보호·노인요양공동생활가정·양로시설은 키워드를 설명하려고 든 이름이고, 나머지는 DB에서 확인한 유형이다.

| 그룹 | 키워드 | 유형 예 |
|---|---|---|
| 방문 서비스 | 방문 | 방문요양서비스, 재가장기요양기관 방문요양, 방문목욕, 방문목욕서비스 |
| 주·야간·단기 보호 | 주야간, 주간보호, 단기보호 | 주·야간보호서비스, 재가 주야간보호, 단기보호 |
| 입소 시설 | 요양시설, 공동생활, 양로, 입소 | 노인요양시설, 노인요양공동생활가정, 양로시설 |

## 자료 형식

- `/api/data?regions=52190,52130`: `{ region: "52190,52130", regions: [코드], regionList: [{ code, sido, name }](256개), facilities, names, population, boundaries }`
- 행정동 경계(`boundaries`, 고른 시군구 것, 경계 파일이 없으면 `[]`): `[{ code: 행정동 10자리, name: 행정동 이름, geometry: GeoJSON Polygon·MultiPolygon }]`
- 시설(`facilities`): DB 노인 돌봄 `{ type, name, lat, lng, dong }` — `type`이 시설 유형이 되고 이름 키워드로 그룹에 묶인다. 의료·보건 `{ type, group: "health", target: "all" | "youthF", name: 유형+번호, lat, lng, dong }` — 그룹·대상이 붙어 온다. `dong` = 좌표가 든 행정동(10자리, 없으면 `null`).
- 행정동 이름(`names`): `{ 행정동 10자리: 이름 }`
- 인구(`population`): `{ month, total, child09, bands, femaleBands, dongs: { 행정동 10자리: { total, child09, bands, femaleBands, lat, lng } } }` — `bands` = 9구간 `{ "0-9", "10-19", "20-29", "30-39", "40-49", "50-64", "65-74", "75-84", "85+" }`, `femaleBands` = 여성 `{ "20-29", "30-39", "40-49" }`, `lat`·`lng` = 대표 지점(경계가 없으면 없음).
- 동작(화면 상태, 저장하지 않음): 추가 `{ id, kind: "add", to, lat, lng, name }`, 전환 `{ id, kind: "convert", from: 기존 시설 id, to, name }` — `to` = 유형 id(DB·파일 유형은 `t:{유형 이름}`, 청년 지원 시설 유형은 `housing`·`jobs`·`school`·`startup`·`culture`), 시설 id = `f:{유형 id}:{위도},{경도}`(같은 자리 여럿이면 `#n`). 이름은 `{유형} 추가 {n}`·`{유형} 전환 {n}`.
- 청년 지원 시설 유형 값(고정 가정값 `INFLOW_SETTINGS`, 화면에서 바꾸지 않음): `{ 유형 id: { settled, living, mix: { "20-29", "30-39", "40-49" } } }`
- 예시 청년 지원 시설(화면이 만듦): `{ type, typeId, group: "youth", target: "youth", name, lat, lng, dong }` — DB 시설과 같은 꼴로 `dbView`에 함께 들어간다.
- 계산 단위(읍면동): `{ id, name, lat?, lng?, pop, elderlyShare, childShare, bands?, femaleBands?, inflow? }` — 대표 지점이 없으면 `lat`·`lng` 없음, `inflow` = 정주인구 유입 `{ 구간: 명 }`(유입이 있을 때만)
- 접근 거리 격자: `{ id, lat, lng, bounds: [[남, 서], [북, 동]], dist }`
